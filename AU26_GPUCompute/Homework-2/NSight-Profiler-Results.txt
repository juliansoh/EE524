Question 26 Answers
============================================================
26(a) Why does kernel execution time differ for shared-memory version versus global-memory version?
Kernel execution time differs because the two kernels use different memory-access patterns and different instruction mixes. Shared-memory versions can reduce repeated global-memory fetches by caching reused data/coefficients in on-chip shared memory, but they also introduce overheads (cooperative loads into shared memory, synchronization, and extra indexing/control logic). Depending on problem size, access pattern, and implementation details, those overheads can outweigh benefits, which is consistent with these measured runs where the static shared-memory kernel is slower.

26(b) Reason about observed differences between naive/global and tiled(shared-memory) using measured execution time, instruction intensity, memory and compute operations.
From the measurements, the shared-memory kernel shows higher instruction intensity (~2x global), meaning it performs more instructions per DRAM byte. Its DRAM traffic remains in a similar range, so the primary change is increased compute/control work rather than a major drop in DRAM bytes. The added shared-memory setup/synchronization and weighted operations increased total cycles/time in this implementation, producing longer execution time than the naive/global version for all four images. In short: this tiled/shared implementation appears more compute/overhead-heavy than memory-limited, so it did not realize a speedup in the current form.
